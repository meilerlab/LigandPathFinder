# Input JSON configuration reference

Both entry points read a single JSON config:

```
python lpf/lpf_coarse_path.py  run.json      # CoarsePathRunner
python lpf/lpf_trajectory.py    run.json      # TrajectoryRunner
```

Any value can be overridden on the command line with dot-notation:

```
python lpf/lpf_trajectory.py run.json --set parameters.step=0.5 --set rosetta_scripts.nstruct_main=20
```

The **Used by** column below is `C` (coarse path), `T` (trajectory), or `C+T`.
See `unused_config_settings.md` for the keys each script *ignores*.
`examples/*/run.json` are minimal working configs — one per run type.

---

## Top level

| Key | Used by | Description |
|-----|---------|-------------|
| `rosetta` | C+T | Absolute path to the `rosetta_scripts` binary. If `n_proc > 1` the filename must contain `.mpi.`. A non-zero exit status from Rosetta aborts the run immediately with the tail of the window's `task.err` / `task.log`. |
| `general_files` | C+T | Directory containing `VRT1.params` (the virtual-atom residue type used for all constraint anchor points). |
| `extra_files` | C+T | List of extra files copied into every Rosetta working directory, e.g. cofactor params (`["../files/HEM.params"]`). Use `[]` if none. |
| `input` | C+T | Input structures and paths — see below. |
| `parameters` | C+T | Algorithm and constraint parameters — see below. |
| `rosetta_scripts` | C+T | Rosetta protocol files and run sizes — see below. |
| `output` | C+T | Output location and run behaviour — see below. |

---

## `input`

| Key | Used by | Description |
|-----|---------|-------------|
| `guide_path` | C+T | Path to the guide curve: either a whitespace-delimited `x y z` text file or a `.pdb` (ATOM/HETATM coordinates). **Coarse** uses only the first and last point; the route between them is generated by recursive bisection. **Trajectory** fits a smoothing spline through all points and resamples it at `step` spacing. |
| `ligand_files` | C+T | Directory holding `lig.params` (Rosetta params for the ligand; its `NBR_ATOM` is the atom tracked along the path) and `lig_conformers.pdb` (pre-generated conformer library). |
| `ligand_chain` | C+T | Chain ID of the ligand in the input PDBs (e.g. `"X"`). **Rosetta never sees this key.** The shipped protocol XMLs hardcode `chain="X"` in `LigandArea`, `SCORINGGRIDS`, `Transform`, `StartFrom` and `InterfaceScoreCalculator`; if you use a different chain you must edit those attributes to match. Both scripts print a warning at start-up when the configured chain does not appear in a protocol. |
| `start_pdb` | C+T | Starting complex (protein + ligand in one file). Provide **either** this **or** the `start_protein_pdb` + `start_ligand_pdb` pair. |
| `start_protein_pdb` | C+T | Protein-only starting PDB. Merged with `start_ligand_pdb` into `start_merged.pdb` at run time. |
| `start_ligand_pdb` | C+T | Ligand-only starting pose PDB, in the frame of `start_protein_pdb`. |
| `header_pdb` | C+T | *Optional.* File whose lines are prepended to every generated `task.pdb` (membrane spans, symmetry records, etc.). Omit or set `false` if unused. |

## `parameters`

### Path geometry

| Key | Used by | Description |
|-----|---------|-------------|
| `step` | C+T | Target spacing between points along the path, in Å. **Coarse:** bisection subdivides a segment until both half-gaps are `< step`. **Trajectory:** spline is resampled to windows `step` apart. |
| `smooth` | T | Smoothing factor `s` passed to `scipy.interpolate.splprep` for the guide-path spline. Larger = smoother / less faithful to the raw points. The trajectory run prints the max turning angle plus what `2×` and `5×` this value would give. |
| `endpoint_jitter` | C | If `true`, displace the path endpoint within a disc (radius `endpoint_jitter_radius`) perpendicular to the path axis, so independent runs land at slightly different endpoints — improves coverage when many runs are pooled and clustered. |
| `endpoint_jitter_radius` | C | Disc radius in Å for `endpoint_jitter`. Ignored unless `endpoint_jitter` is `true`. |

### Conformer sampling

| Key | Used by | Description |
|-----|---------|-------------|
| `conformer_subsampling` | C+T | If `true`, before each Rosetta call filter `lig_conformers.pdb` down to conformers within `conformer_rmsd_threshold` of the current ligand pose (speeds up sampling for flexible ligands). If `false`, the full library is used every time. |
| `conformer_rmsd_threshold` | C+T | RMSD cutoff (Å) for `conformer_subsampling`. Ignored unless subsampling is on. |

### RMSD (shape) constraint

Restrains each ligand atom toward its position in the incoming reference pose,
via one `AtomPair` per atom to a per-atom ghost virtual atom. Acts as a soft
whole-ligand RMSD restraint.

| Key | Used by | Description |
|-----|---------|-------------|
| `rmsd_constraint` | C+T | Master on/off switch. (Always forced `false` for the dock-zero / window-0 dock step, where the incoming pose is not yet trustworthy.) |
| `rmsd_constraint_type` | C+T | `"harmonic"` (spring to the reference position) or `"bounded"` (flat well then quadratic). |
| `rmsd_constraint_bound` | C+T | Half-width (Å) of the flat region; used only when `rmsd_constraint_type == "bounded"`. |
| `rmsd_constraint_sd` | C+T | Base standard deviation (Å); the effective per-atom weight is `sd·√N`. **Coarse** additionally scales it by `√(dL/step)` per node (looser over larger gaps). **Trajectory** retries a failed window with `sd·0.2`, `sd·0.04`. |
| `rmsd_constraint_hydrogens` | C+T | If `false`, hydrogens are excluded from the restraint. |

### In-plane-deviation constraint (ipdc)

One `AtomPair` between the ligand `NBR_ATOM` and the target point for the
current step, keeping the ligand near the guide point / inside the bisection
plane.

| Key | Used by | Description |
|-----|---------|-------------|
| `in_plane_dev_constraint` | C+T | Master on/off switch. |
| `ipdc_type` | C+T | `"bounded"` or `"harmonic"`. **Coarse always uses `"bounded"`** — any other value is ignored (with a warning). |
| `ipdc_d0` | T | Flat-well radius (Å) for the bounded form. **Coarse ignores the config value** and recomputes it per node as `0.5·dL` (`dL` = node distance to its target). |
| `ipdc_sd` | T | Constraint standard deviation (Å). **Coarse ignores the config value** and recomputes it per node as `0.1·dL`. |
| `end_padding` | T | Distance (Å) over which the in-plane constraint is relaxed as the trajectory approaches the endpoint: the last `int(end_padding/step)` windows get a linearly shrinking `ipdc_d0`, and the terminal window snaps harmonically to the endpoint. `0` disables. **Coarse ignores this** (treated as `0`, with a warning). |

### Plane (coplanarity) constraint

Three `Dihedral` constraints tie the ligand `NBR_ATOM` into the plane of a
virtual equilateral triangle placed in the bisection / guide plane.

| Key | Used by | Description |
|-----|---------|-------------|
| `plane_constraint_point_extent` | C+T | Circumradius (Å) of the virtual triangle. Larger = stiffer, better-conditioned coplanarity restraint. |
| `plane_constraint_sd` | C+T | Standard deviation (radians) of the three dihedral constraints (target dihedral 0). Small values (`~0.02`) enforce the plane tightly. |

### Direction (angle) constraints

Both target a straight angle (π); `bound` is the lower limit in radians
(e.g. `2.65 rad ≈ 152°`, so the angle is held between 152° and 180°).

| Key | Used by | Description |
|-----|---------|-------------|
| `angle_constraint` | C+T | On/off. **Coarse:** `Angle(prev_neighbour — NBR — next_neighbour)` — keeps the ligand between its two path neighbours. **Trajectory:** `Angle(prev_prev — prev — NBR)` — penalises back-tracking. |
| `angle_constraint_type` | C+T | `"bounded"` or `"harmonic"`. |
| `angle_constraint_bound` | C+T | Lower angle bound (radians); used only for `"bounded"`. |
| `angle_constraint_sd` | C+T | Standard deviation (radians). |
| `next_angle_constraint` | C+T | On/off for the second angle term. **Coarse:** `Angle(second-neighbour — neighbour — NBR)` on each side. **Trajectory:** `Angle(prev — NBR — next)` — keeps forward progress aligned with the guide. |
| `next_angle_constraint_type` | C+T | `"bounded"` or `"harmonic"`. |
| `next_angle_constraint_bound` | C+T | Lower angle bound (radians); `"bounded"` only. |
| `next_angle_constraint_sd` | C+T | Standard deviation (radians). |

### Pose propagation & selection

| Key | Used by | Description |
|-----|---------|-------------|
| `memory_mode` | C+T | If `true`, the full best decoy (including any protein relaxation) is carried forward to the next step, so induced protein motion accumulates along the path. If `false`, only the ligand coordinates are transplanted onto the original protein via `swap_lig_coords`, and each step restarts from the same protein conformation. |
| `select_best_by` | C+T | Score used to pick the best decoy: `"total_score"` or `"interface_delta_X"`. Constraint energies are subtracted before ranking. |
| `select_next_by` | T | Same choice, for the decoy that is *propagated* to the next window (may differ from the one reported). |
| `outlier_rmsd` | T | Reject decoys whose ligand `NBR_ATOM` has drifted more than this (Å) from the window's target position before selection. |
| `noise` | T | If `true`, add Gaussian noise (sd `= step·0.33`) to the projected previous point before each main window — helps escape local traps. |
| `skip` | T | If `true`, skip windows where the guide path folds back on itself (plane-crossing angle > 90°). |

### Optional pre-docking

| Key | Used by | Description |
|-----|---------|-------------|
| `dock_zero` | C+T | If `true`, first dock the ligand onto the guide path's first point (using `protocol_zero_dock` / `nstruct_zero`) before the main algorithm starts. Use when the starting structure has the ligand present but not yet positioned. Requires `rosetta_scripts.protocol_zero_dock` and `rosetta_scripts.nstruct_zero`. |

## `rosetta_scripts`

| Key | Used by | Description |
|-----|---------|-------------|
| `options` | C+T | Rosetta `@`-options (flags) file, copied into each working directory. |
| `protocol` | C | RosettaScripts XML run at every coarse-path node. |
| `protocol_zero` | T | XML for window 0 when `dock_zero` is `false` (typically a minimise-only protocol). |
| `protocol_main` | T | XML for all normal trajectory windows. |
| `protocol_stats` | T | XML run for the optional per-window statistics pass (see `run_stats`). |
| `protocol_zero_dock` | C+T | XML for the pre-docking step; required only when `dock_zero` is `true`. |
| `nstruct` | C | Decoys generated per coarse-path node. |
| `nstruct_main` | T | Decoys per trajectory window. |
| `nstruct_stats` | T | Decoys for the statistics pass; required only when `run_stats` is `true`. |
| `nstruct_zero` | C+T | Decoys for the pre-docking step; required only when `dock_zero` is `true`. |
| `n_proc` | C+T | MPI ranks. Must be a positive integer and `≤` the relevant `nstruct`. `> 1` requires an `.mpi.` Rosetta binary. |
| `mpi_launcher` | C+T | Launcher command used when `n_proc > 1` (e.g. `"mpirun"`). |

## `parameters.run_stats` / statistics pass

| Key | Used by | Description |
|-----|---------|-------------|
| `run_stats` | T | If `true`, after each window run `protocol_stats` (`nstruct_stats` decoys) on the selected pose and record separate stats score arrays into `stats.pkl`. |

---

## `output`

| Key | Used by | Description |
|-----|---------|-------------|
| `path` | C+T | Output directory. Created if absent; all per-node / per-window subdirectories and the final trajectory files are written here. |
| `verbose` | C+T | Extra progress logging. Default `true`. |
| `archive` | C+T | If `true`, `zip -rm` each node/window directory after it finishes, to save inodes. |
| `checkpoint_interval` | T | Save a resumable checkpoint every N completed windows. `0` disables. A run auto-resumes from `checkpoint.pkl` in `path` unless started with `--fresh`. |
| `use_tmp` | T | If `true`, execute each window in a temporary directory (RAM disc by default) and copy results back to `path` on completion. |
| `tmp_path` | T | Explicit temporary location for `use_tmp`. Empty string → try `/dev/shm`, then `/run/shm`. |

---

## Outputs written to `output.path`

**Coarse path:** `coarsepath.txt` (point sequence), `trajectory.pdb`,
`lig_trajectory.pdb`, `full_trajectory.pdb`, and one numbered directory per node.

**Trajectory:** `guide_path` / `spline` / `normals` / `input_path`,
`nbr_trajectory.txt`, `total_scores.txt`, `interface_scores.txt`, `stats.pkl`,
`lig_trajectory.pdb`, `full_trajectory.pdb`, `checkpoint.pkl`, and one
`window_XXXX` directory per window.
