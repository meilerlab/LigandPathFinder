# Config settings that are ignored per script

The two entry points — `lpf_coarse_path.py` (`CoarsePathRunner`) and
`lpf_trajectory.py` (`TrajectoryRunner`) — share one JSON config schema
(`full_input.json`), but each script reads only a subset of it. This file lists
the keys that are **silently ignored** or **overridden** by each script so that a
config tuned for one stage is not assumed to behave the same way in the other.

"Ignored" below means: present in the schema, read by the *other* script, but not
consulted here (or consulted and then overwritten). Keys that are simply
inactive because their enabling flag is `false` are listed separately under
*Conditional*.

For what each key *does*, see [`config_reference.md`](config_reference.md).

---

## `lpf_coarse_path.py` (CoarsePathRunner)

### Overridden — value in the config has no effect

| Key | What actually happens |
|-----|-----------------------|
| `parameters.ipdc_type` | Always forced to `"bounded"`. A warning is printed if the config sets anything else. |
| `parameters.end_padding` | Forced to `0` (end padding is a trajectory-only feature). A warning is printed if the key is present. |
| `parameters.ipdc_d0` | Recomputed per node as `0.5 * dL` (`0.5 * step` in dock-zero), where `dL` is the node's distance to its target. Warning already emitted by `_validate_config`. |
| `parameters.ipdc_sd` | Recomputed per node as `0.1 * dL` (`0.1 * step` in dock-zero). Same warning. |
| `parameters.rmsd_constraint_sd` | Used, but scaled per node by `sqrt(dL / step)`. |

### Ignored — not read at all

| Key | Reason |
|-----|--------|
| Intermediate guide-path points | Only `guide_path[0]` and `guide_path[-1]` are read. The path between the endpoints is generated by recursive bisection, not taken from the file. |
| `parameters.smooth` | No spline fitting; the raw endpoints are used directly. |
| `parameters.noise` | No per-window projection noise in the coarse stage. |
| `parameters.skip` | No turn-back skip logic. |
| `parameters.run_stats` | No stats stage. |
| `parameters.select_next_by` | Coarse selects only a single "best" pose; there is no separate "next" pose propagated forward. |
| `parameters.outlier_rmsd` | `ScoreParser.report_final` is called without this argument, so its default (`100`, effectively off) is used. |
| `rosetta_scripts.protocol_zero` | Trajectory-only protocol name. |
| `rosetta_scripts.protocol_main` | Trajectory-only protocol name. Coarse uses `rosetta_scripts.protocol`. |
| `rosetta_scripts.protocol_stats` | No stats stage. |
| `rosetta_scripts.nstruct_main` | Coarse uses `rosetta_scripts.nstruct`. |
| `rosetta_scripts.nstruct_stats` | No stats stage. |
| `output.checkpoint_interval` | No checkpoint / resume support in the coarse stage. |
| `output.use_tmp` | No tmp / RAM-disc staging in the coarse stage. |
| `output.tmp_path` | Same. |

### Conditional — inactive unless their flag is set

- `parameters.rmsd_constraint_type`, `rmsd_constraint_bound`,
  `rmsd_constraint_hydrogens`, `rmsd_constraint_sd` — only when
  `rmsd_constraint` is `true`. `rmsd_constraint_bound` additionally only when
  `rmsd_constraint_type == "bounded"`.
- All `ipdc_*` handling — only when `in_plane_dev_constraint` is `true`.
- `parameters.angle_constraint_bound` — only when
  `angle_constraint_type == "bounded"`; likewise
  `next_angle_constraint_bound` for `next_angle_constraint_type`.
- `parameters.conformer_rmsd_threshold` — only when
  `conformer_subsampling` is `true`.
- `parameters.endpoint_jitter_radius` — only when `endpoint_jitter` is `true`.
- `rosetta_scripts.protocol_zero_dock`, `rosetta_scripts.nstruct_zero` — only
  when `parameters.dock_zero` is `true`.
- During dock-zero specifically, `parameters.rmsd_constraint` is forced to
  `false` regardless of the config.
- `input.start_pdb` vs (`input.start_protein_pdb` + `input.start_ligand_pdb`) —
  whichever set is not used for the chosen start mode is ignored.

## `lpf_trajectory.py` (TrajectoryRunner)

### Ignored — not read at all

| Key | Reason |
|-----|--------|
| `parameters.endpoint_jitter` | Coarse-only ensemble-diversity feature. |
| `parameters.endpoint_jitter_radius` | Same. |
| `rosetta_scripts.protocol` | Coarse-only protocol name. Trajectory uses `protocol_zero` / `protocol_main` / `protocol_stats` (and `protocol_zero_dock` when `dock_zero`). |
| `rosetta_scripts.nstruct` | Coarse-only. Trajectory uses `nstruct_main` / `nstruct_stats` / `nstruct_zero`. |

### Note — behaves differently from coarse

- `parameters.ipdc_d0` and `parameters.ipdc_sd` **are** honoured here (used as
  literal constraint parameters), unlike in the coarse stage where they are
  recomputed per node.
- `parameters.ipdc_type` **is** honoured here (`"bounded"` or `"harmonic"`),
  unlike in the coarse stage where it is forced to `"bounded"`.
- `parameters.end_padding` **is** honoured here: it softens the in-plane
  constraint over the final `int(end_padding / step)` windows. `0` disables it.

### Conditional — inactive unless their flag is set

- `parameters.rmsd_constraint_type`, `rmsd_constraint_bound`,
  `rmsd_constraint_hydrogens` — only when `rmsd_constraint` is `true`;
  `rmsd_constraint_bound` additionally only when
  `rmsd_constraint_type == "bounded"`.
- All `ipdc_*` handling and `end_padding` — only when
  `in_plane_dev_constraint` is `true`.
- `parameters.angle_constraint_bound` / `next_angle_constraint_bound` — only
  when the matching `*_type` is `"bounded"`.
- `parameters.conformer_rmsd_threshold` — only when `conformer_subsampling` is
  `true`.
- `parameters.noise` — only affects the main (non-zero, non-terminal) windows.
- `parameters.skip` — only active when `true`.
- `parameters.run_stats`, `rosetta_scripts.protocol_stats`,
  `rosetta_scripts.nstruct_stats` — only when `run_stats` is `true`.
- `rosetta_scripts.protocol_zero_dock`, `rosetta_scripts.nstruct_zero` — only
  when `parameters.dock_zero` is `true`. When `dock_zero` is `true`,
  `protocol_zero` is not used for window 0; `rmsd_constraint` is forced `false`
  for window 0 and `outlier_rmsd` is treated as infinite for window 0.
- `output.tmp_path` — only when `output.use_tmp` is `true`.
- `output.checkpoint_interval` — `0` disables checkpointing.
- `input.start_pdb` vs (`input.start_protein_pdb` + `input.start_ligand_pdb`) —
  whichever set is not used for the chosen start mode is ignored.
